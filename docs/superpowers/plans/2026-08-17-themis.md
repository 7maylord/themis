# Themis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Uniswap v4 pool where MEV-sensitive swaps route through Flashbots Protect with refunds split to an LP vault, and where the hook itself charges toxic flow a risk premium that is donated back to LPs — built to a mainnet deployment standard.

**Architecture:** Three contracts. `ThemisRisk` is a pure math library (EWMA volatility, normalized risk score, hysteresis, premium curve). `ThemisHook` uses exactly two permission bits (`afterSwap`, `afterSwapReturnDelta`), maintains O(1) per-pool risk state, and diverts a risk-scaled premium from the unspecified currency into `FairShareVault`. `FairShareVault` accrues both that premium and native-ETH Flashbots refunds, then returns them to LPs with `poolManager.donate()` — no share accounting, no claim flow. Offchain is one Next.js app; the risk engine exists **only** onchain and is read via `previewRisk` eth_call. There is no backend, no database, and no `ThemisRouter`.

**Tech Stack:** Solidity 0.8.26, Foundry (`via_ir = false`, cancun), Uniswap v4 core/periphery via `lib/v4-hooks-public`, OpenZeppelin (Ownable/Pausable/ReentrancyGuard), Medusa, Slither, Next.js 16, wagmi 2, viem 2, TailwindCSS 4.

**Spec:** [`themis-prd-trd.md`](../../../themis-prd-trd.md) — read it alongside this plan. Where they disagree, this plan wins; every deviation is recorded in "Deviations From The Spec" below.

## Global Constraints

- Solidity `0.8.26`, `evm_version = "cancun"`, `optimizer_runs = 800`, `via_ir = false`, `ffi = true` — already set in `foundry.toml`, do not change.
- Hook permission bits are **exactly** `AFTER_SWAP_FLAG | AFTER_SWAP_RETURNS_DELTA_FLAG`. Any additional bit requires re-mining the address and re-justifying the audit surface.
- Base pool fee: `500` (0.05%, v4 units are hundredths of a bip). Max Themis premium: `2500` ppm (0.25%). Worst-case total trader cost 0.30% — never above a vanilla 0.30% pool. Enforce the cap in the setter with `require`, not a comment.
- Risk score domain is `[0, 100]` inclusive, `uint32`. This is an invariant, not a convention.
- All fixed-point math uses `FullMath.mulDiv`. No raw `*` then `/` on user-controlled values.
- No unbounded loops. Every state write in the swap path is O(1).
- No secrets in git. `FLASHBOTS_AUTH_PRIVATE_KEY` is a backend-only searcher key and is never a user wallet key.
- The UI must never claim the hook verified Flashbots provenance, and must never auto-broadcast a protected swap publicly.
- Never present simulated economics as onchain results. Every number rendered carries a `source: "onchain" | "fork-sim" | "controlled"` tag.
- Commit convention: one Conventional Commits subject line, no body, no AI attribution trailer.
- Never run `git push`. Commit and stop.

## Feasibility Findings That Shaped This Plan

Verified against current Flashbots docs on 2026-08-17.

1. **The spec's AMBER submission flow is unimplementable.** FR-006 forbids the backend holding keys, and `POST /v1/transactions/private` requires `{ rawTransaction }`. MetaMask refuses `eth_signTransaction` as a deliberate design decision, so a browser wallet cannot produce that input. **Resolution:** the trader's wallet points at the Protect RPC directly, with the FairShare split encoded in the RPC URL. Zero backend.
2. **Refund splitting is real and needs no onchain plumbing.** Protect RPC supports `?refund=ADDRESS:PERCENTAGE` (repeatable, percentages must sum to <100). Default without it: 90% of MEV refund to `tx.origin`, 10% to the validator.
3. **Sepolia has no meaningful refund market.** Flashbots documents a Sepolia bundle relay and notes they run only a small portion of testnet validators. Private *inclusion* is provable on Sepolia; organic *refunds* are not. Economics therefore come from mainnet-fork tests, and the live refund is demonstrated with a controlled bundle.
4. **Consequence — the hook must move value itself.** If FairShare arrives only via an RPC query parameter, the hook is a logger and FairShare revenue on Sepolia is structurally zero. Hence the onchain risk premium: toxic flow pays, GREEN flow does not, and value reaches LPs with or without a searcher.
5. **Large reuse available in `../eleos`.** `test/utils/{BaseTest,Deployers}.sol`, `script/base/{BaseScript,LiquidityHelpers}.sol`, the `HookMiner` deploy pattern, `medusa.json`, and the Next 16 + wagmi frontend shell are all proven and directly portable.

## Deviations From The Spec

| Spec says | Plan does | Why |
|---|---|---|
| Backend receives raw signed tx (§20) | Wallet points at Protect RPC; no backend | MetaMask cannot produce a raw signed tx |
| NestJS + Prisma + PostgreSQL + Docker (§16, §19, §23) | Deleted | Only irreducible backend need was the auth key; finding 1 removes it |
| Risk engine offchain **and** onchain (§9, §19) | Onchain only, read via `previewRisk` | Two implementations of one EWMA will drift |
| `ThemisRouter.sol` (§17.3) | Deleted; use canonical v4 router | See note below — this row gets questioned every time |
| `beforeSwap` + `afterSwap` permissions (§17.1) | `afterSwap` + `afterSwapReturnDelta` | `afterSwap` can recompute everything; fewer bits, smaller audit surface |
| Hook is telemetry; fee policy "optional" (§17.1) | Hook charges a risk premium and funds the vault | Otherwise FairShare is zero without searchers |
| LP distribution is post-MVP (§8.4) | `poolManager.donate()` ships in v1 | A vault nobody can withdraw from is not mainnet-grade |
| `hookData` struct carrying offchain quote (§18) | Deleted | Hook is self-contained; untrusted input with no consumer is pure attack surface |
| TS/Python simulation harness (§24) | Foundry fork tests emitting JSON | Avoids a second implementation of the pool math |
| Backend persists route/status/provenance (FR-011) | Read from chain events on demand | No backend exists to persist to; Sepolia log volume is trivial to query directly |
| `maxBlockNumber` on submission (FR-007) | Protect's `blockRange` query param | Same intent — bounded retry window — expressed in the URL form Protect actually accepts |

**On `ThemisRouter` specifically** — this looks like it should be the flagship contract and it isn't, so the distinction is worth stating once. Themis has *two* things a reader can conflate under "router":

1. **Route selection** (GREEN vs AMBER) — this is the actual premise. It happens before any transaction exists, as a choice of which RPC endpoint receives the signed tx. No contract can make this decision; it lives in `frontend/lib/protect.ts` (Task 9), matching the PRD's own §14.2 architectural claim that the SDK/API owns routing, not the hook.
2. **`ThemisRouter.sol`** (spec §17.3) — a swap-execution passthrough: deadline, slippage bounds, forward `hookData`. This is infrastructure, not the mechanism, and the canonical v4 router already does it — the spec even warns "do not reimplement Universal Router." It is deleted, not the premise it sounds like.

If a future EIP-712 intent design (spec's "open question" §37.6, gestured at in Task 9's step 1 comment) replaces wallet-signed transactions, a settlement contract becomes genuinely necessary — but that contract validates signatures and enforces trader limits, which is a different job than §17.3 ever described.

`src/ThemisRisk.sol`:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.26;

import {FullMath} from "@uniswap/v4-core/src/libraries/FullMath.sol";

/// @title ThemisRisk
/// @notice Pure risk math for Themis. No storage, no external calls, fully fuzzable.
/// @dev Scores are in [0, 100]. Rates are in basis points unless the name says ppm.
library ThemisRisk {
    uint256 internal constant BPS = 10_000;
    uint32  internal constant MAX_SCORE = 100;

    uint8 internal constant GREEN = 0;
    uint8 internal constant AMBER = 1;
    uint8 internal constant RED   = 2;

    // Hysteresis band (spec §9.6). Entry thresholds are strictly above exit thresholds
    // so a trader cannot oscillate across a single boundary to reprice themselves.
    uint32 internal constant GREEN_TO_AMBER = 35;
    uint32 internal constant AMBER_TO_GREEN = 25;
    uint32 internal constant AMBER_TO_RED   = 70;
    uint32 internal constant RED_TO_AMBER   = 60;

    // Composite weights (spec §9.3), summing to 100.
    uint32 internal constant W_VOL    = 30;
    uint32 internal constant W_SIZE   = 25;
    uint32 internal constant W_IMPACT = 30;
    uint32 internal constant W_FLOW   = 15;

    /// @notice Absolute price move between two sqrtPriceX96 values, in bps.
    /// @dev price = sqrtPrice^2, so ratio_price = (new/prev)^2. Computed as two
    ///      mulDivs to keep the intermediate inside uint256 for the full tick range.
    function priceReturnBps(uint160 prevSqrtPrice, uint160 newSqrtPrice)
        internal
        pure
        returns (uint256)
    {
        if (prevSqrtPrice == 0 || newSqrtPrice == 0 || prevSqrtPrice == newSqrtPrice) return 0;

        uint256 sqrtRatio = FullMath.mulDiv(uint256(newSqrtPrice), BPS, uint256(prevSqrtPrice));
        uint256 priceRatio = FullMath.mulDiv(sqrtRatio, sqrtRatio, BPS);

        return priceRatio > BPS ? priceRatio - BPS : BPS - priceRatio;
    }

    /// @notice Exponentially weighted moving average (spec §9.5).
    function ewma(uint256 prevBps, uint256 sampleBps, uint256 alphaBps)
        internal
        pure
        returns (uint256)
    {
        if (alphaBps > BPS) alphaBps = BPS;
        return (alphaBps * sampleBps + (BPS - alphaBps) * prevBps) / BPS;
    }

    /// @notice Linear map of a bps quantity onto [0, 100], clamped at fullScale.
    function normalize(uint256 valueBps, uint256 fullScaleBps) internal pure returns (uint32) {
        if (fullScaleBps == 0) return 0;
        if (valueBps >= fullScaleBps) return MAX_SCORE;
        return uint32(FullMath.mulDiv(valueBps, MAX_SCORE, fullScaleBps));
    }

    /// @notice Weighted composite risk score, clamped to [0, 100].
    function composite(uint32 volScore, uint32 sizeScore, uint32 impactScore, uint32 flowScore)
        internal
        pure
        returns (uint32 score)
    {
        unchecked {
            score = (volScore * W_VOL + sizeScore * W_SIZE + impactScore * W_IMPACT + flowScore * W_FLOW) / 100;
        }
        if (score > MAX_SCORE) score = MAX_SCORE;
    }

    /// @notice Regime transition with hysteresis. Returns the new regime.
    function nextRegime(uint32 score, uint8 currentRegime) internal pure returns (uint8) {
        if (currentRegime == GREEN) {
            if (score >= AMBER_TO_RED) return RED;
            return score >= GREEN_TO_AMBER ? AMBER : GREEN;
        }
        if (currentRegime == AMBER) {
            if (score >= AMBER_TO_RED) return RED;
            return score <= AMBER_TO_GREEN ? GREEN : AMBER;
        }
        return score <= RED_TO_AMBER ? AMBER : RED;
    }

    /// @notice Risk premium in ppm, charged only above the GREEN boundary and
    ///         ramping linearly to `maxPremiumPpm` at score 100.
    /// @dev GREEN flow is never surcharged. This is the product promise; keep it exact.
    function premiumPpm(uint32 score, uint24 maxPremiumPpm) internal pure returns (uint24) {
        if (score < GREEN_TO_AMBER) return 0;
        uint256 span = MAX_SCORE - GREEN_TO_AMBER;
        return uint24(FullMath.mulDiv(uint256(score - GREEN_TO_AMBER), uint256(maxPremiumPpm), span));
    }
}
```

The `afterSwap` risk update, in order:

1. `PoolId poolId = key.toId();`
2. Read `(uint160 sqrtPriceX96,,,) = poolManager.getSlot0(poolId);` and `uint128 liq = poolManager.getLiquidity(poolId);` via `StateLibrary`.
3. **Volatility** — only when `block.number > st.lastUpdatedBlock`: `sample = ThemisRisk.priceReturnBps(st.lastSqrtPrice, sqrtPriceX96)`, then `volBps = ThemisRisk.ewma(volBps, sample, alphaBps)`, `volatilityScore = normalize(volBps, volFullScaleBps)`. On the very first swap (`lastSqrtPrice == 0`) record the price and leave volatility at 0.
4. **Size** — `absAmount = amountSpecified < 0 ? uint256(-amountSpecified) : uint256(amountSpecified)`; `sizeScore = normalize(mulDiv(absAmount, BPS, liq), sizeFullScaleBps)`. Guard `liq == 0` → score 0.
5. **Impact** — `impactScore = normalize(priceReturnBps(st.lastSqrtPrice, sqrtPriceX96), impactFullScaleBps)`. This is the realized move of *this* swap, updated every swap even when volatility is block-capped.
6. **Flow** — `flowScore = normalize(ewma(flowBps, BPS, flowAlphaBps), flowFullScale)` where the sample is `BPS` on every swap and decays by block gap. Concretely: decay first by `min(block.number - lastUpdatedBlock, 64)` applications is a loop — **do not loop**. Instead store `flowEwma` and apply a single decay proportional to the block gap: `flowEwma = mulDiv(flowEwma, BPS, BPS + gap * flowDecayPerBlockBps)`, then `flowEwma = ewma(flowEwma, BPS, flowAlphaBps)`. O(1), monotone, and it rises with swaps-per-block — which is exactly the split-swap signal.
7. `score = ThemisRisk.composite(volatilityScore, sizeScore, impactScore, flowScore)`.
8. `regime = ThemisRisk.nextRegime(score, st.regime)`.
9. Write state, set `lastSqrtPrice`, `lastUpdatedBlock`, emit `RiskUpdated` + `ThemisSwapObserved`.
10. Return `(BaseHook.afterSwap.selector, 0)` — the delta is Task 5.

`previewRisk` runs steps 4–8 against **current** state without writing, using the current `slot0` price for impact. Factor the scoring into an `internal view _score(...)` that both paths call, so they cannot drift.

Mechanics, verified against the working pattern in `../eleos/src/RecaptureHook.sol:240-297`:

The premium is charged in the **unspecified** currency. `poolManager.take(currency, address(vault), amount)` gives the hook a `-amount` delta; returning `+amount` as the hook delta credits the hook `+amount`, netting to zero. The swapper absorbs it — as less output on exact-input swaps, or more input on exact-output swaps. Either way the router's `amountOutMinimum` / `amountInMaximum` still bounds the trader, so slippage protection covers the premium. This is why no separate trader guard is needed.

Which currency is unspecified:
- `zeroForOne && exactInput` → currency1
- `!zeroForOne && !exactInput` → currency1
- `!zeroForOne && exactInput` → currency0
- `zeroForOne && !exactInput` → currency0

i.e. unspecified is currency1 exactly when `zeroForOne == exactInput`. Handle **both** branches; eleos only implements the currency1 branch, and copying that limitation would silently drop the premium on half of all swaps.

// The FairShare split lives in the Protect RPC URL. Percentages must sum to <100
// (Flashbots constraint); the remainder follows Flashbots builder/validator economics.
export function buildProtectRpcUrl(opts: {
  vault: `0x${string}`;
  vaultPercent: number;
  hints?: string[];
}): string {
  const { vault, vaultPercent, hints = ["hash"] } = opts;
  if (!Number.isInteger(vaultPercent) || vaultPercent < 1 || vaultPercent > 99) {
    throw new Error("vaultPercent must be an integer in [1, 99]");

  const url = new URL("https://rpc-sepolia.flashbots.net/");
  for (const h of hints) url.searchParams.append("hint", h);
  url.searchParams.append("refund", `${vault}:${vaultPercent}`);
  url.searchParams.append("originId", "themis");
  return url.toString();
}
